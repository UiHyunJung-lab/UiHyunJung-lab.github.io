## 🚨 오늘의 개발 일지: 최종 AAB 추출 전 마지막 점검
전체 코드 수정이 끝나고, 오늘 드디어 GistInfoApp의 최종 AAB 파일을 구글 플레이 콘솔에 업로드하였다. 
하지만 결코 금방 끝난 작업은 아니었다. 진짜 AAB를 추출하기 전에 앱의 전반적인 사이클을 점검하였고, 그 과정에서 구글 플레이 심사에 반려될 수 있는 2가지 미흡한 점을 발견하여 보완에 들어갔다.

<br>

## 🐛 트러블 슈팅 및 빌드 에러 해결

### 1. 위치 권한 소명 및 게시판 이용규칙 동의 로직 추가
* **위치 권한 사전 알림**: 기존에는 위치 버튼을 누르면 곧바로 안드로이드 OS의 권한 탭이 떴다. 하지만 구글 정책상 권한을 왜 요구하는지 앱 자체적인 설명이 필요하므로, 권한 요청 직전에 **자체 알림 메시지**를 띄우고 동의 시에만 OS 권한 탭이 뜨도록 수정하였다.
* **게시판 이용규칙**: 게시판 최초 진입 시 이용규칙에 동의하는 화면을 추가했다. 동의 기록을 저장하여 들어갈 때마다 매번 누르는 번거로움을 없앴고, 미동의 시에는 게시판을 이용할 수 없도록 막았다.

### 2. 비회원 로그인 우회 버그 픽스
게시판 이용규칙을 추가하는 과정에서 치명적인 논리 버그가 등장했다.
* **문제 상황**: 비회원으로 구경하다가 게시판에 진입 -> 로그인을 요구받아 로그인 화면이 뜸 -> 로그인 후 '이용규칙 동의 화면'에서 [동의하지 않음]을 클릭 -> 이전 화면(로그인 창)이 꺼지면서 **자연스럽게 게시판으로 무단 진입이 되어버리는 버그**였다. 
* **해결 방법**: 이용규칙에 동의하지 않을 시 단순히 화면 스택을 뒤로 가게(`goBack()`) 두는 것이 아니라, 무조건 **앱의 홈 화면으로 강제 이동**하도록 라우팅 로직을 수정하여 우회 진입을 완벽히 차단했다.

### 3. 악명 높은 Hermes 빌드 에러와의 사투
코드를 고치고 개인정보 처리방침 노션까지 업데이트한 후 대망의 AAB 빌드를 시도했는데, 예상치 못한 **Hermes 에러**가 발생했다.
* **원인 파악**: 이전부터 다른 팀원들의 PC에서 빌드가 실패했던 원인이기도 했다. 메타 측에서 React Native의 새 버전을 만들 때, `node_modules` 내에 Hermes 관련 파일이 제대로 담기지 않고 누락되어 발생하는 고질적인 이슈였다. 내 노트북에서는 지금까지 어떻게 빌드가 됐었는지 미지수지만, 온갖 방법을 써봐도 빌드가 번번이 실패했다.
* **해결 방법 (우회)**: 최후의 수단으로 **Hermes 엔진을 사용하지 않고 빌드**하기로 결단했다. Hermes는 RN 코드를 더 빠르게 읽는 최적화 엔진이지만 필수 요소는 아니기 때문에, `build.gradle` 등에서 Hermes 속성을 `false`로 끄고 빌드한 결과 마침내 AAB 추출에 성공했다!

<br>

## 💦 아쉬운 점과 배운 점
Hermes 에러 때문에 원인을 찾고 빌드를 재시도하느라 엄청난 답답함과 시간을 소모했다. 하지만 기술적인 이슈에 매몰되지 않고, 엔진을 끄는 플랜 B를 선택하여 '배포'라는 현재의 가장 중요한 목표를 달성해 낸 점은 큰 수확이다. 코딩만큼이나 유연한 판단력도 중요하다는 것을 배웠다.

<br>

## 🚀 앞으로의 계획
소중하게 만들어진 최종 AAB 파일을 구글 플레이 콘솔에 업로드하였고, 검토를 위해 구글에 심사를 넣었다. 
이제 심사 결과를 기다리는 동안, 정식 출시의 마지막 관문인 **비공개 테스트를 진행할 테스터들을 모집**하고 테스트를 본격적으로 운영할 계획이다. 기대가 된다!
